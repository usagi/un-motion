# U.N. Motion 操作ガイド

## 想定ユーザー

- Web カメラだけでアバターを動かしたい VStreamer / VTuber / virtual avatar user
- U.N. Avatar と組み合わせて、軽量で扱いやすい webcam mocap 環境を作りたい民
- VMC 対応アプリへ体・顔・手のモーションを送りたい民
- 自作ツールや研究用途で U.N. Motion Frame を受け取りたい開発者

## できること

- Web カメラから 頭、顔、手、腕、胴体、脚、足 をお好みで必要な部分だけ推定して UNMF/Z や VMC/UDP あるいは VRChat (VRCFT) で出力できます。
- 他のアプリから VMC を受け取って、頭、顔、手、腕、胴体、脚、足 の単位でフィルターやスムージングをかけつつ UNMF/Z や VMC/UDP で出力できます。
- U.N. Avatar や他のアバターアプリと UNMF/Z または VMC/UDP で接続でき、 VRChat (VRCFT) への表情の直接送信もできます。
- 複数のカメラや推定エンジンをプロファイルとして保存しておいて、用途に合わせて切り替えたり同時に使えます。
- ポージング/モーションを録画して再生できます。

## ここが嬉しい

- 軽量で高速: 一般的なゲーミングPCなら高性能なカメラを接続して90fps程度の推定をCPU2コア負荷ほどほど、メモリー200MB程度で動作可能です。
- 豊富な補正機能: パラメーター調整可能な複数の方法でのスムージング、フェイス姿勢補正モデルによる高精度な頭と顔の姿勢推定、部位単位での出力フィルターなど。
- 通常のモーション出力は、推定した姿勢・表情を送ります。入力画像の保存は既定で無効です。診断用の追加情報を有効にしたSnapshot記録では、入力画像も保存されます。

## 一般的な使い方

WindowsのSupervisor設定画面には **Microsoft Edge WebView2 Runtime** が必要です。未導入の場合は[Microsoft公式ページ](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section)からEvergreen Runtimeを導入して再起動してください。Edgeブラウザー本体とは別の実行環境です。Capturerや推定エンジンの依存ファイルも、配布物の構成を保ったまま使用してください。

Windows x64版には **Microsoft Visual C++ v14 Redistributable（x64）** も必要です。`MSVCP140.dll`、`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll`、`CONCRT140.dll` がないというエラーが出る場合は、[Microsoft公式のダウンロード案内](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/)から最新のx64版を導入し、U.N. Motionを起動し直してください。Visual Studio本体のインストールは不要です。

1. `un-motion-supervisor.exe` を起動します。
2. `プロファイルと稼働` でプロファイルを選びます。追加する場合は `新規` を押します。
3. カメラ、推定エンジン、出力先を設定します。
4. 編集対象の名前を確認し、稼働欄の `このプロファイルを起動` を押します。Capturer は、入力から動きを取得して送信する処理です。
5. 必要に応じて顔姿勢補正モデルや U / T / I キャリブレーションを作成します。
6. U.N. Avatarなどの受信側で、アバターが動くことを確認します。取得が始まらない場合はCapturerの状態とログ、取得中でも動かない場合は受信側の入力設定を確認してください。

`全稼働個体` は、起動済みの Capturer をまとめて確認・操作する画面です。最初の設定と起動は `プロファイルと稼働` で進められます。

同じPCのU.N. AvatarとはUNMF/Zの自動接続をそのまま利用できます。LAN内の別PCで自動接続できない場合は、
使用中profileのUNMF/Z Publisherで「LAN内の別PCから直接接続を許可」をONにし、表示された接続先を
受信側アプリのアドレス指定接続へ入力します。

## 入力や姿勢保持の詳細を調整する

### 動画ファイルを入力に使う場合

動画ファイルの読み込みには **FFmpeg**、動画のサイズや長さの解析には **ffprobe** を使います。この配布物には含まれません。「設定」のFFmpeg欄から用意した `ffmpeg.exe` を指定し、同じフォルダーに `ffprobe.exe` もあることを確認してください。入手先は設定画面のFFmpeg公式サイトへの入口から確認できます。プロファイルごとの指定は、下記の「専用FFmpeg」を使います。

通常のDirectShowカメラ入力のために、FFmpegを追加する必要はありません。カメラ推定に使うMediaPipeのDLLと `models` フォルダーは配布物に含まれます。EXEだけを移動せず、配布フォルダー全体を保って使ってください。

「プロファイルと稼働」で編集対象を選ぶと、MediaPipeの入力設定の近くに「入力の詳細」、シグナルロスト設定の近くに「後処理とホールドの詳細」があります。閉じた状態でも、専用FFmpegの指定や拡縮・後処理・ホールドの有効状態を確認できます。

| やりたいこと | 操作と適用範囲 |
| --- | --- |
| 特定の入力だけ別のFFmpegを使う | 「入力の詳細」の「専用FFmpeg」に実行ファイルの場所を指定します。このプロファイルの指定が共通設定より優先されます。 |
| アプリ共通のFFmpegへ戻す | 「共通設定を使う」を押すか、専用FFmpegを空欄にします。他のプロファイルの専用指定は変わりません。 |
| 静止画像の入力サイズを調整する | 拡縮を有効にして、基準の方向・サイズ、出力枠、縦横比、余白の色を指定します。サイズの空欄は自動値です。これらは静止画像専用で、動画・カメラには適用されません。 |
| 部位別ホールドが働かない理由を確認する | 「後処理とホールドの詳細」の許可を確認します。許可がOFFなら、部位別にホールドを選んでも保持しません。 |
| 後処理を省いて比較する | 「MediaPipeの後処理」で「後処理を使わない」を選びます。通常へ戻す場合は「既定を使う」を選びます。後処理を省くと、その経路の補正も働かなくなります。 |

入力値は選択中のプロファイルへ自動保存されます。稼働中への受け渡しに失敗しても、保存済みの値まで失われたとは限りません。保存通知と以下の対象・復旧手順を確認してください。

## 複数プロファイル・Capturer を使う場合

プロファイルは保存する設定、Capturer はその設定で起動したモーション取得・送信処理です。例えばカメラ入力用と VMC 入力用を別プロファイルで用意し、両方を起動できます。

| 対象 | 意味 |
| --- | --- |
| 編集中のプロファイル | 設定を書き換える対象。変更は自動保存されます。 |
| 起動ボタンの対象 | 「プロファイルと稼働」では選択中のプロファイル。「全稼働個体」からの起動では、起動用に選んだプロファイルまたはグループ。 |
| アプリ再起動後の選択 | 最後に保存できた編集対象。選択の保存に失敗した場合は以前の対象が残ります。 |
| 稼働中の Capturer | すでに動いている個体。停止・再起動やキャリブレーションは対象個体を確認して操作します。 |

`このプロファイルを起動` を押すと、`全稼働個体` の共通の起動指定もそのプロファイルに変わります。グループを起動したい場合は、同画面で起動対象をグループに選び直してください。すでに動いている個体には影響しません。

`新規` で作成したプロファイルは、次回Supervisorを起動した際の選択対象にもなります。これはCapturerの自動起動を意味しません。別のプロファイルを選択して保存できれば、次回の選択もその対象になります。

同じ名前やメモのプロファイルは `ID:` で区別できます。起動対象の選択にはプロファイルID、稼働一覧と選択中のCapturerにはプロファイルIDと個体番号・PIDが表示されます。同じプロファイルから複数起動した場合は、個体番号・PIDまで確認してください。

プロファイルの選択を変えるだけでは、稼働中の Capturer は切り替わりません。一方、設定を編集すると、そのプロファイルを使う稼働個体への反映を送ります。同じプロファイルを複数起動している場合は、一つの個体だけの変更にはなりません。稼働個体がなければ次回起動に使われます。

保存と稼働個体への反映は別です。「設定は保存済み」「受け渡しを確認できません」と表示された場合は、示された Capturer の稼働状態を確認してください。保存後の画面更新失敗も、保存失敗とは異なります。未保存の失敗では、エラーと残った入力を確認してから再保存してください。

### 保存を確認できなかった入力

「保存を確認できなかった入力」の各項目を開くと、元の対象、入力値、失敗の内容を確認できます。別プロファイルを選んでも再保存先は変わりません。通信が途切れた場合は保存自体が成功している可能性もあるため、対象の保存内容を確認してから操作してください。保持した入力はウィンドウを閉じると失われます。

- 別の操作による変更と競合した場合は「最新の保存内容を確認」で比較し、必要な値を新しい編集として入力します。確認だけでは上書きしません。
- 通常の保存失敗では「この対象へ再保存」を使えます。後の編集と重なった古い入力は、そのまま再試行できません。内容を参照して、必要な変更を改めて入力してください。
- 詳細設定の数値や色が無効な場合は保存されず、元の入力がここに残ります。「入力した対象を開く」で修正し、不要になった元の入力を破棄してください。
- 不要になった記録は「保持した入力を破棄」で消します。保存中は破棄できません。破棄しても保存済み設定は巻き戻りません。

保存待ち・保存失敗の入力が残る対象は、複製・削除の前に保存または破棄を完了してください。他のプロファイルに残る入力は、その操作を妨げません。

ここでの説明は、このリポジトリの現行実装に対応します。配布済みの旧版とは表示や対応範囲が異なる場合があります。

### モーション記録を書き出した後の警告

記録本体の保存後に、追加の診断ファイルや「前回使った保存先」の記憶だけが失敗する場合があります。エラーに `Motion recording saved to ...` と表示された場合、その場所には記録本体が保存済みです。続く説明で失敗した処理を確認してください。追加診断まで保存できたという意味ではありません。本体の書き込みに失敗した場合は、この保存済み表示は出ません。

## カメラについて

更新前の設定退避と旧版へ戻す方法は [更新・バックアップ・復元](update-and-recovery.md) を参照してください。EXEを別フォルダーに置くだけでは、設定の保存先は分離されません。

通常の 30 fps Web カメラでも動作しますが、モーションの安定性はカメラ品質の影響をかなり受けます。

- 「60 fps 以上」のカメラがおすすめです。
- ローリングシャッターより「グローバルシャッター」の方が安定しやすいです。
- 暗い部屋や強い逆光では推定が不安定になりやすいです。服装や背景からなんとなく推定して貰いやすそうだなと思える準備がカメラ性能と同等かそれ以上に重要です。
- 手や指を使いたい場合は、手のひらが見える明るさと解像度がかなり重要です。(320x240より640x480くらいがよいです。それより大きい解像度は必要ありません。)
- Tポーズでキャリブレーションしたい、デスクトップでも手を広げて動かしたい、全身を狭い空間で動かしたい場合などは、広角レンズ搭載の Webcam がおすすめです。

おすすめカメラの例:

- [ELP 1080P 90FPS Global Shutter Camera / 2.8f 120deg 640x480@90fps MJPG](https://amzn.to/4dmWfAL)
- または何はともあれ [グローバルシャッターのカメラ](https://amzn.to/4uUemDU)
- もしUSB接続などでWebcam化できるコンデジ/デジカメ/アクションカメラをお持ちなら並のWebcamより良い感じに使える事もあります。

Windowsのカメラ映像入力には **DirectShow** を選んでください。MediaFoundationは機器情報を確認するための選択肢で、現行版ではカメラ映像からの推定に未対応です。MediaFoundationを選んだプロファイルがある場合は、DirectShowへ変更し、使うカメラと対応する解像度・FPSを確認してからCapturerを起動してください。

## 開発者向け

ビルドには **Rust 1.100.0** を使用します。`rust-toolchain.toml` に従って rustup が選択します（最低対応バージョン: 1.100、プロジェクト内コードの Edition: 2024）。依存関係は `Cargo.lock` を維持し、検証時は `cargo check --locked` / `cargo test --locked` を使用してください。

Cargoの中間生成先 `build-dir` を実行ファイルの出力先と分離する場合は、`UN_BUILD_PROFILE_DIR` に実行ファイルを配置するディレクトリの絶対パスを指定してください。

この repository には Supervisor GUI、Capturer runtime、MediaPipe Native bridge、入力、Modifier、出力、release tooling が含まれています。

よく使うコマンド:

```sh
cargo xtask verify
cargo run
cargo xtask make-release-package --version 1.1.0
```

MediaPipe Native DLL を更新する場合:

```sh
cargo xtask mediapipe build-native
```

Supervisor の UI を HMR で編集する場合:

```sh
cd apps/un-motion-supervisor
npm install
npm run tauri dev
```

## 診断用の入力画像保存

「設定」の詳細にある「入力画像を含む診断情報もSnapshotと保存する」は、既定ではOFFです。ONにしてSnapshotを記録すると、MediaPipeへ渡す入力画像（PNG）とランドマークなどの解析情報も記録します。画像は保存先を選ぶ前に一時フォルダーへ生成され、保存時には記録本体に対応する `.analysis-assets` フォルダーへ移されます。保存をキャンセルした場合と保存が成功した場合は、その記録用の一時フォルダーを削除します。保存に失敗した場合は復旧のために一時データを残し、エラーにその場所を表示します。強制終了した場合の一時データは自動削除の対象になりません。通常の姿勢・表情の記録とは内容が異なります。診断ファイルを他の人へ渡す場合は、画像に映った内容も確認してください。

## 診断ログ

配布版のSupervisorログは `%APPDATA%/UN Motion/logs` に保存されます。`UN_MOTION_CONFIG_DIR` で保存先を指定した場合は、そのフォルダー内の `logs` を使います。「ログ」画面から保存・保存先の表示ができます。
